# Профили инструментов

Начните с core. Для ежедневной работы в терминале macOS рекомендуем отдельно
добавить terminal и Ghostty. Любой профиль — выбор пользователя, а не обязательный
чек-лист. Точный состав CLI хранится только в [manifests](../manifests/macos/cli/).

| Профиль | Зачем выбирать |
| --- | --- |
| core | Git, доставка конфигурации chezmoi, управление проектными версиями mise |
| terminal | Prompt Starship, история Atuin, поиск fzf/fd/rg, zoxide, просмотр diff через Delta |
| shell-extras | Небольшие autosuggestions и syntax highlighting; можно обойтись штатным zsh |
| tmux | SSH, переподключения и длительные сессии; не запускается сам |
| monitoring | btop для интерактивного обзора, dust для исследования занятого места |
| build | CMake/Ninja/pkg-config/GNU Make, когда проекту недостаточно Apple CLT |
| python-uv | uv для зависимостей Python; сам Python и его версия определяются проектом |
| neovim | Для пользователя, который действительно редактирует в терминале; без готового plugin distro |
| git-ui | lazygit как опциональный интерфейс поверх Git; CLI Git достаточно для базы |
| automation | hyperfine для измерений, watchexec для наблюдения за файлами, just для проектов с Justfile |
| cli-extras | Дополнительные viewers, обработка данных и GitHub CLI; без алиасов |
| secrets | age/sops для конкретного workflow зашифрованных файлов, ключи отдельно |

Пример: `./bootstrap macos install terminal python-uv build`.
Core автоматически добавляется. Имена проверяются до первой установки.
`./verify macos terminal python-uv build` проверяет только выбранный набор.
Список установленного не записывается обратно в manifests.

## Что не включено без необходимости

bottom и btop решают похожую задачу; выбран один btop в опциональном monitoring.
`duf`/`procs`/`watch` не нужны для bootstrap: системные `df`/`ps`/`top` доступны.
`dust` полезен для исследования диска, но не заменяет `du` в скриптах.
`hyperfine` уместен для сравнения времени выполнения; не нужен на каждой машине.

`just` не дублирует задачи этого репозитория: здесь достаточно `mise run check`.
Он предусмотрен только для чужих проектов, использующих Justfile.
`watchexec` добавляется для локального цикла разработки при необходимости.
Neovim/lazygit не считаются обязательной второй средой рядом с VS Code.

Go/Node/Python, gopls, linters, sqlc, миграции, OpenSSL, базы данных и локальные AI
модели зависят от проекта. Отдельных глобальных установок `@latest` для них нет.
Ollama и любые другие сервисы устанавливайте и запускайте только под задачу.
Shell frameworks, font packs и несколько конкурирующих терминалов не нужны базе.

Homebrew управляет macOS CLI; mise — проектными runtimes и, при необходимости,
точными версиями инструментов проекта. Не устанавливайте одну и ту же утилиту
одновременно глобально через brew, mise, uv tool и самостоятельный installer.
Подробнее о закреплении версий — [проекты](projects.md).

На других Unix это описание возможностей, а не готовый список пакетов для apt
или pacman. Будущий адаптер должен сопоставить пакет с исполняемым файлом
(например, `fd` против `fdfind`), проверить версии и источник обновлений.
