# Повторные запуски, обновления и восстановление

## Перед первой миграцией

Сохраните текущие пользовательские данные обычным резервным копированием.
`common diff` может показать старые секреты из конфигурации: просматривайте вывод
локально, не прикладывайте его целиком в публичный issue.

При переходе со старого README отдельно проверьте:

- `~/.gitconfig`: core.ignorecase/fileMode, старые excludesFile, diff.tool,
  credential helpers, signing, aliases. Через `git config --show-origin --get KEY`
  найдите источник конкретного значения, затем отредактируйте только нужную запись.
  Repo не удаляет вашу identity и настройки другого менеджера credentials.
- `.zshenv`, `.zprofile`, `.zshrc`, `.zimrc`: старые init hooks, alias-модули,
  `PAGER=bat`, дубли Homebrew, fzf install hooks. Diff заменяет управляемые файлы;
  перенесите нужные локальные особенности в source осознанно. Zim-каталог не удаляется.
- VS Code: старые auto-approve/auto-reply/auto-accept сохраняются, пока вы их не
  сбросите в соответствующем User/Workspace/Remote scope.
- Уже установленные Docker CLI, GUI-дубликаты и сервисы: проверьте владельца
  установки. Bootstrap не удаляет существующие программы, данные или сервисы.

Изменения README, существовавшие до этой работы, сохранены локально в
`.git/pre-bootstrap-readme.patch`; полный исходный working-file — объект Git
`5680efe8f55016146a793a1d8fa2b380475466a4`. Это локальные страховочные данные этой
миграции, не часть переносимого bootstrap. Atuin возвращён согласно новому заданию;
в исходном working-file он уже был удалён, что отражено в [аудите](audit.md).

## Поведение apply

`init` создаёт только локальные параметры и состояние chezmoi. `diff` не меняет
управляемые файлы; у chezmoi могут появиться служебные cache/state-файлы.
`apply` показывает актуальный diff и требует точное слово `apply`. EOF и любой
другой ответ отменяют операцию. При совпадении файлов повторный apply заканчивается
успешно без новых backups. Не запускайте несколько apply/restore одновременно и
не редактируйте source или destination между просмотром diff и применением.

Перед записью создаётся закрытый каталог
`~/.local/state/unix-setup/backups/snapshot.XXXXXXXX`. В нём:

- `files/` — оригиналы существовавших managed files с режимами и symlinks;
- `present` / `absent` — какие файлы существовали и какие будут созданы;
- `complete` — признак завершённого backup.

Имена целевых файлов берутся у chezmoi, второго списка dotfiles нет. Обёртка
поддерживает только простые относительные имена внутри source. Домашний каталог
и путь checkout могут содержать пробелы. Нестандартные managed filenames
отклоняются. Symlink-родители и directory вместо управляемого файла отклоняются;
symlink самого файла сохраняется и может быть восстановлен.

Новые parent directories создаются с umask 077. Режимы существующих директорий
не переписываются. Chezmoi применяет только files/symlinks и не запускает scripts.
Операция не является транзакцией: если приложение/диск/процесс прервал применение,
часть файлов могла уже измениться. Завершённый backup остаётся доступен.

## Восстановление

```sh
./bootstrap common restore snapshot.XXXXXXXX
```

Подставьте имя, напечатанное при apply. Команда показывает, какие файлы вернёт,
а какие удалит как отсутствовавшие до apply, и ждёт слово `restore`. Перед этим
сохраните новые ручные изменения: restore намеренно возвращает состояние snapshot.
Неполные backups и небезопасные пути отвергаются. После восстановления проверьте
`common diff`; несовпадение с текущим source ожидаемо. Следующий apply снова
предложит source-версию, поэтому сначала исправьте source, если откатываете ошибку.

Restore использует сырые резервные копии для аварийного восстановления;
обычные обновления dotfiles по-прежнему проходят только через chezmoi.
Пакеты, runtime downloads, история, cache, пустые каталоги и параметры выбора
chezmoi не откатываются. Ключи и данные приложений требуют собственного backup.
При сломанном startup откройте `/bin/zsh -f` или `/bin/sh`; если проблема именно
в `.zshenv`, используйте `/bin/sh`, который его не читает.

## Обновления

Сначала просмотрите изменения репозитория, включая scripts/templates/manifests,
затем `common diff` и `common apply`. Не выполняйте слепой `chezmoi update`.

```sh
# Только уже установленные CLI из core + названных профилей:
./bootstrap macos update terminal python-uv
# GUI отдельно и по именам:
./bootstrap macos gui update ghostty vscode
# Проверка выбранного состава:
./verify macos terminal python-uv
./verify common
```

CLI update сначала обновляет метаданные brew, затем выбранные installed formulae.
Неустановленные пакеты пропускаются; добавление новых — через `macos install`.
Фактические зависимости Homebrew могут обновиться вместе с выбранной formula.
`brew upgrade` без списка и `bundle cleanup --force` не используются.

Brewfile описывает желаемый набор, а не lockfile бинарных версий. Поэтому bootstrap
повторно запускаем, но не обещает побитового воспроизведения предыдущей машины.
Откат версии пакета Homebrew не гарантируется; восстановление конфигурации не
восстанавливает старую БД или совместимость приложения. Проверяйте release notes
и резервные копии данных. Проектные runtimes/зависимости закрепляются отдельно
в mise/uv/npm/Go manifests и lockfiles.

## Проверки репозитория

`./verify repo` проверяет формат **без записи**, синтаксис sh/Bash 3.2 и конфигов,
целостность каталогов, реальные diff/apply/restore через chezmoi в scratch HOME,
идемпотентность, symlinks, отмену и SSH signing с одноразовым тестовым ключом.
Инсталляторы и shell integrations в тестах подменены контролируемыми заглушками.
Тест не устанавливает tools, не использует ваш SSH-agent и не читает ваш Git config.

CI настроен для Ubuntu и macOS ARM. Только одноразовые CI runners получают тестовые
зависимости: pinned chezmoi с SHA-256, Python и zsh. Реальная установка macOS-стека,
GUI, Keychain, подключение к Git-host и запуск сервисов не выполняются тестами.
Проверка этих операций остаётся приёмкой на отдельной чистой тестовой системе.
