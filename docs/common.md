# Общая конфигурация

Сначала определите роль машины и нужные инструменты. Общая часть управляет
пользовательскими файлами, а платформенная — установкой пакетов и интеграцией ОС.
Порядок чтения начинается здесь; фактический запуск на чистом Mac начинается
с [подготовки macOS](macos.md).

## Поддержка и зависимости

| Среда | Реализовано | Ограничения |
| --- | --- | --- |
| macOS, Apple Silicon, 14+ | Подготовка, CLI-профили, GUI, dotfiles, проверки | Версии ОС и пакеты должны поддерживаться их поставщиками; 14 — нижняя граница, а не обещание поддержки каждого GUI |
| macOS Intel, 14+ | Выбор `/usr/local`, тот же сценарий | Best effort; Homebrew Tier 3; чистая установка здесь не проверена |
| Linux с POSIX userland | Только общие dotfiles при наличии зависимостей | CI проверяет Linux; нет apt/pacman/systemd/bootstrap ОС |
| Другие Unix/BSD | Архитектура допускает перенос | Не объявлены протестированными; сначала проверить доступность и версии инструментов |
| SteamOS / Proxmox host / Ubuntu guests | Только [контракт расширения](platforms.md) | Специальные установщики ещё не реализованы |

Общие скрипты используют `/bin/sh` и POSIX utilities: `id`, `dirname`, `mkdir`,
`cp`, `rm`, `cat`, `awk`; дополнительно требуется BSD/GNU-совместимый `mktemp -d`.
Нет Bash-массивов, `readlink -f`, `sed -i`, `xargs -r`, GNU `stat` или `find -printf`.
На macOS подходит системный Bash 3.2 при явном запуске `/bin/bash bootstrap …`.
Сами startup files требуют zsh; тесты — Python 3.11+ и zsh 5.9.

До `common apply` нужны Git 2.35+ (включая `zdiff3`), chezmoi 2.x и mise с
поддержкой `settings.paranoid`. Используйте текущие поддерживаемые версии.
Для terminal UX нужен fzf 0.48+ и инструменты профиля. Проверьте сборки под свою
архитектуру; наличие бинарника в пакетном менеджере не доказывает поддержку ОС.

Запуск — только из обычного аккаунта, без root/sudo. У аккаунта должны быть
права на собственный домашний каталог. Автоматического применения к root нет.
Поддерживаются стандартные `~/.config`, `~/.local/{share,state}`, `~/.cache` и
`ZDOTDIR=$HOME`; нестандартные XDG-пути и symlink-каталоги в управляемых путях
отклоняются до применения. Это явное ограничение небольшой реализации.

## Структура и владение файлами

```text
bootstrap, verify                  точки входа
scripts/                           общие операции и восстановление
platforms/macos/                    проверки macOS и работа с Homebrew
dotfiles/                          единственный chezmoi source
  .chezmoitemplates/macos/          только конфигурация macOS
manifests/macos/cli/*.Brewfile       независимые CLI-профили
manifests/macos/gui.tsv             единственный каталог GUI
manifests/editors/                  опциональные расширения
config/editors/                     образец настроек редактора
docs/, tests/                      правила, источники, безопасные проверки
```

Один пакет явно перечислен только в одном CLI-профиле; зависимости Homebrew могут
пересекаться. Отдельного агрегированного Brewfile и `brew bundle dump` поверх
manifests нет. В `dotfiles/` нет install hooks, `run_once` или внешних downloads.
Шаблоны macOS включаются из общего source только для macOS, без копий конфигов.

## Применение

После установки зависимостей запустите `common init`, выберите `zsh`, `terminal`,
`tmux`, `ghostty`. Выбор конфигурации не устанавливает соответствующие программы.
По умолчанию на macOS включены zsh и конфигурация Ghostty; terminal и tmux выключены.
На Linux всё опциональное выключено. Для рекомендуемого macOS-маршрута установите
профиль `terminal` и ответьте `yes` на вопрос terminal UX. `apply` проверяет
его зависимости до изменения dotfiles, чтобы не настроить Git pager на отсутствующий Delta.

Выбор сохраняется в `~/.config/unix-setup/chezmoi.toml`. Повторный `init` его
сохраняет. Чтобы изменить выбор, отредактируйте этот локальный файл, затем выполните
`common diff` и `common apply`. Отключение опции прекращает управление файлами,
но не удаляет ранее применённые файлы; используйте восстановление или удалите
конкретные файлы вручную после просмотра. Удалений «всего лишнего» нет.

Обёртка всегда указывает source текущего checkout и отдельную базу состояния
`~/.local/state/unix-setup/`. Ваш другой chezmoi source не перенастраивается.
Пользуйтесь командами обёртки: обычный `chezmoi apply` может обращаться к другому
репозиторию. Не управляйте одним целевым файлом из двух source.

## Git

Общие настройки находятся в `~/.config/git/config`: ветка `main`, prune при fetch,
pull только fast-forward и конфликты `zdiff3`. Это консервативные предпочтения;
переписывание истории, autostash и автоматический push не включены.

Git читает также `~/.gitconfig`, который имеет более высокий приоритет.
Он не перезаписывается. Поэтому старые настройки из предыдущего README могут
продолжать действовать: [порядок миграции](recovery.md).
Личные overrides можно хранить в неуправляемом `~/.config/git/local`.
[Правила чтения конфигурации Git](https://git-scm.com/docs/git-config).

Настройте настоящее имя и email локально, например через `git config --global --edit`.
`user.useConfigOnly=true` запрещает Git угадывать вашу identity. Signing включается
отдельно после [проверки ключа](ssh.md), а не заранее с несуществующим файлом.

Глобальный ignore содержит только `.DS_Store` и AppleDouble `._*`.
`.vscode`, `.idea`, `.env`, `dist`, `node_modules`, lockfiles и исходники не скрываются
глобально. Политику исключений определяет каждый проект. Даже локальный ignore
не является защитой от публикации секрета.

## Shell

- `.zshenv`: только два значения по умолчанию для EDITOR/PAGER, без вывода и команд.
- `.zprofile`: login PATH; Homebrew подключается только шаблоном macOS.
- `.zshrc`: интерактивная история, completions и доступные интеграции.

Используется системный zsh без Zim/Oh My Zsh: для этого набора менеджер модулей
не нужен. Пользовательские shell/Git-алиасы и одноимённые замены стандартных
команд отсутствуют. Используйте `bat`, `eza`, `rg`, `fd`, `dust` собственными именами.
`z project` — явная навигация zoxide; `cd` сохраняет стандартное поведение.

Ctrl-R вызывает Atuin, Ctrl-T и Alt-C — fzf. Его history binding выключается
**до** подключения `fzf --zsh`; без Atuin остаётся стандартный поиск zsh.
Atuin не перехватывает Up, выбранная команда сначала попадает в строку редактирования.
На клавиатурах, где Option вводит символы, настройте модификатор в Ghostty
осознанно; без этого можно пользоваться `fd` и `fzf` напрямую.
[fzf integration](https://github.com/junegunn/fzf#setting-up-shell-integration),
[Atuin key binding](https://docs.atuin.sh/latest/configuration/key-binding/).

Для filenames с пробелами, кавычками и переводами строки используйте NUL-протокол,
например `fd --type f --print0 | fzf --read0 --print0`. Не передавайте результат
через `awk -F:` и whitespace-`xargs`. Интерактивные Ctrl-T/Alt-C здесь используют
штатные виджеты fzf; в автоматизации с произвольными именами нужен NUL-протокол.

tmux запускается только явно. Для удалённого сервера дополнительно проверьте его
terminfo и поддержку терминала; это не повод автоматически переписывать `TERM`.
Агенты и скрипты используют [явные mise-команды](projects.md), не `.zshrc`.
